## 1. 背景与决策

Jia him 是部署在 Vercel 的 VitePress 纯静态站点，Markdown 和媒体保存在 GitHub 仓库。站点所有者需要比直接编辑文件更顺手的写作体验，但不需要数据库、远程管理服务或额外账号体系。

最终采用轻量本地方案：在 monorepo 中保留公开站点 `apps/site`，新增仅本机启动的 `apps/admin`。工作台直接读写当前 Git worktree，利用本机 Git 和 GitHub CLI 完成版本控制、推送、Pull Request 和发布。公开站点仍然只有静态产物，管理端不会部署到 Vercel，也不会暴露在公网。

## 2. 产品目标

- 提供接近主流 Markdown 编辑器的桌面写作体验。
- Markdown 继续作为唯一内容源，不引入数据库或第三方 CMS。
- 管理端只监听回环地址，本机之外不可访问。
- 所有文章和媒体修改都进入当前 worktree，可被 Git 检查、提交和恢复。
- 将“保存文件”“提交并推送”“合并并发布”明确分开，避免误发布。
- 通过内容分支、Pull Request、Vercel Preview 和合并保留完整审计记录。

## 3. 成功标准

- 现有中文文章能被完整列出、搜索、打开和编辑；任意层级 `index.md` 不进入列表。
- 默认三栏：左侧文章列表、中间 Markdown 源码、右侧实时预览与大纲。
- 左侧文章列表可一键收起为窄栏，编辑和预览区域自动扩展，并可再次展开。
- 编辑器具有语法高亮、快捷键、行号、查找、撤销/重做和合理的光标体验。
- 保存后文件立即落盘；异常关闭后可恢复尚未保存的本地草稿。
- Git 状态只展示当前仓库真实状态；提交只暂存当前文章及本次上传的媒体。
- 推送只发生在非默认内容分支；界面不得 force push、reset、rebase、stash 或全仓暂存。
- PR 合并前必须再次明确确认；合并后由 Vercel 自动发布公开站点。
- `pnpm build:site` 与 `pnpm build:admin` 均通过，公开产物不包含管理入口。

## 4. 用户故事与验收条件

### 4.1 浏览文章

- 左栏顶部包含“文章”“新建”和收起按钮。
- 支持按标题、摘要、文件路径搜索，以及按分类筛选。
- 列表显示分类、标题、日期和未保存/未提交状态。
- 长标题使用紧凑单行截断，不挤压日期和状态；悬停时可查看完整标题。

### 4.2 编辑文章

- 中栏始终是 Markdown 源码编辑器，不用写作/预览二选一切换。
- 标题、日期、摘要可直接编辑；未知 frontmatter 字段保存时保留。
- 编辑器支持 Markdown 高亮、括号补全、代码块缩进、行号、查找和常用快捷键。
- `Cmd/Ctrl+S` 保存当前文件；`Cmd/Ctrl+P` 聚焦文章搜索。
- 页面离开或切换文章时，未保存内容必须提醒。
- 浏览器本地保存恢复副本，成功落盘后清除对应恢复副本。

### 4.3 实时预览与大纲

- 右栏实时渲染标题、摘要和正文，不执行正文内原生 HTML 或脚本。
- 右栏可在“预览”和“大纲”之间切换；大纲来自正文标题。
- 点击大纲项使编辑器定位到对应标题。
- 编辑区和预览区提供可关闭的滚动同步。
- 站内绝对路径图片使用本地站点地址展示。

### 4.4 保存与媒体

- “保存”只写入当前 worktree，不提交、不推送、不发布。
- 新文章按分类、日期和 slug 创建 Markdown 文件。
- 图片支持 PNG、JPEG、GIF、WebP、AVIF，单文件最大 8 MB。
- 图片保存到 `docs/public/images/articles/{YYYY}/{MM}` 并自动插入 Markdown。
- 本次上传媒体进入当前编辑会话的可提交文件集合。

### 4.5 Git 版本控制

- 顶部展示当前分支、已修改文件数和同步状态。
- “查看差异”展示当前文章的 worktree diff；历史面板展示文章提交记录。
- 当前处于默认分支时，“提交并推送”先创建 `content/YYYY-MM-DD-slug` 内容分支。
- 提交只包含当前文章和本次会话上传的媒体。
- 默认提交信息为 `[Human] docs: <文章标题>`，允许用户修改。
- 使用本机 Git/SSH 推送，并通过本机 `gh` 创建或复用 Pull Request。
- detached HEAD、merge/rebase、冲突或无远端时禁用写操作，并给出终端处理提示。

### 4.6 发布

- 提交并推送后展示 PR 链接和 Vercel Preview 提示。
- “合并并发布”与“提交并推送”是两个独立按钮。
- 有未保存内容、未推送提交、冲突或 PR 检查未完成时不能合并。
- 合并前明确展示目标 PR 和目标分支并二次确认。
- 通过 `gh pr merge --squash --delete-branch` 合并，不得绕过分支保护。

## 5. 页面结构

### 5.1 顶栏

- 品牌、本地工作区标识。
- 保存状态、查看差异、提交并推送、合并并发布。

### 5.2 左栏：文章列表

- 默认宽度约 300 px，可收起为贴左边界的窄分隔轨道。
- 收起状态仅在轨道右侧保留紧凑展开按钮。
- 展开状态包含搜索、分类统计和文章列表。

### 5.3 中栏：Markdown 源码

- 顶部显示源码/专注入口、字数和草稿恢复状态。
- 元数据与正文在同一滚动上下文内呈现。
- 默认占三栏剩余空间约 55%。

### 5.4 右栏：预览与大纲

- 默认宽度约 34%，最小 320 px。
- 顶部包含预览/大纲切换和滚动同步状态。
- 窄屏时允许切换成单面板，文章列表以抽屉形式出现。

## 6. 非功能要求

- 使用 TypeScript、pnpm workspace 和 Node.js 22+。
- 管理端仅绑定 `127.0.0.1`，不得提供生产部署配置。
- 文件路径限制在允许的文章和媒体目录内。
- 执行 Git/`gh` 时使用参数数组，不通过 shell 拼接用户输入。
- 管理端不读取或存储 GitHub Token；认证沿用本机 Git/SSH 与 `gh auth`。
- 常用桌面分辨率下三栏无需横向滚动。

## 7. 首期范围

### P0

- 本地三栏编辑工作台与可折叠文章列表。
- CodeMirror Markdown 编辑器、实时预览、大纲和基础快捷键。
- 本地草稿恢复、未保存提醒、文章搜索与筛选。
- 新建、保存和图片上传。
- Git 状态、当前文章 diff、文章历史。
- 安全内容分支、精确暂存、提交、推送、创建 PR、合并发布。
- 构建、类型检查、单元测试和关键交互测试。

### 后续优化

- 可拖拽调整三栏宽度并持久化。
- 命令面板、Markdown 格式化命令和模板。
- 图片资源库、粘贴图片、未使用媒体检测。
- Vercel Preview/Checks 的更细状态展示。

### 不在范围

- 部署管理端、远程登录、多用户与权限系统。
- 数据库、对象存储或第三方 Headless CMS。
- 实时协同编辑、移动端完整写作体验。
- 从 UI 暴露任意 Git 命令或破坏性历史操作。

## 8. 发布阶段

1. 在独立 worktree 中完成文档、测试和实现。
2. 本地启动管理端，验收三栏、折叠、编辑、预览与只读 Git 信息。
3. 使用临时 Git 仓库测试提交工作流，不触碰真实远端。
4. 经用户明确授权后，才提交、推送和创建 PR。
5. 合并后确认 Vercel 静态站点构建及现有 URL 未变化。

## 9. 规格变更规则

本 PRD 为已确认实施基线。涉及管理端是否联网部署、Git 写入范围、发布语义、内容存储或三栏信息架构的变更，必须先更新 PRD 和设计文档。

## 10. v1.1：仓库可视化管理与站点设置中心

### 10.1 产品定位扩展

本地工作台不再只覆盖文章编辑，而是成为“当前 Git 仓库的安全可视化管理 UI”。它仍然不是远程 CMS：不部署管理端、不引入数据库、不保存云端秘密，也不直接调用 Vercel API。所有可发布状态都以仓库文件为事实来源，并沿用 Git、Pull Request、Vercel Preview 和生产分支发布链路。

VitePress 继续作为公开网站的渲染与构建核心。工作台修改结构化配置、Markdown 和公开资源；VitePress 在构建时读取这些文件并生成导航、侧边栏、页面元数据、SEO/GEO 输出和静态站点。

### 10.2 统一配置源

- 新增 `config/site.config.json`，作为所有可公开站点设置的唯一事实来源。
- 配置必须包含 `schemaVersion`，由共享 TypeScript Schema 提供类型、默认值、校验和后续迁移。
- `docs/.vitepress/config/*` 改为适配层，不再分别硬编码栏目、导航和站点公开信息。
- 工作台和 VitePress 必须消费同一 Schema；两者不得维护重复栏目常量。
- 配置保存前必须通过完整校验；无效配置也必须使公开站点构建失败并输出可定位错误。

### 10.3 设置中心范围

设置中心覆盖常见个人内容网站的公开配置：

- 基础资料：站点名称、描述、站点域名、作者及个人简介。
- 品牌资源：Logo、favicon、默认分享图和替代文本。
- 栏目管理：名称、稳定 ID、目录、路由、排序、层级、显示状态、默认折叠和归档状态。
- 导航管理：顶部导航、外部链接、显示顺序和打开方式。
- 首页管理：首页模块、显示顺序、推荐文章和可见状态。
- 外观设置：默认主题模式、强调色、内容布局和代码主题。
- SEO：标题模板、默认描述、canonical、索引策略、Open Graph、sitemap 和结构化数据。
- GEO：AI 爬虫策略、机器可读输出、作者与来源信号、AI 引用友好检查和 AI 来源流量识别。
- 页脚与社交：版权、备案信息、友情链接和社交账号。
- 集成：分析工具等仅包含公开标识的配置，以及秘密环境变量是否存在的只读状态。
- 高级信息：配置版本、校验结果和原始 JSON 只读预览。

### 10.4 栏目扩展要求

- 后台新增栏目时，同时更新共享配置并创建 `docs/zh/<directory>/index.md`。
- 新栏目自动进入网站导航、网站侧边栏、编辑器目录树和新建文章分类。
- 网站和编辑器必须保持栏目顺序、层级、名称及文章路径一致。
- 编辑器左栏默认显示真实目录树；搜索或“全部文章”模式可以提供扁平结果。
- 栏目使用稳定 ID。名称和排序可修改；栏目已有文章后，物理目录默认锁定。
- 普通“删除”只允许隐藏或归档，不得自动删除栏目目录及已有文章。
- 物理目录迁移属于独立高风险流程，未来实现时必须生成 URL 重定向并单独确认。
- 第一版只编辑中文站点，但数据结构必须预留 `locale` 和未来语言映射，不实现一键翻译。

### 10.5 设置中心交互

- 顶部提供“文章管理 / 站点设置”主模式切换。
- 文章模式保持三栏：网站一致的目录树、Markdown 编辑、预览/大纲/文章级 SEO-GEO 检查。
- 设置模式保持三栏：设置分组、配置表单、实时预览/校验/Git Diff。
- 所有表单修改先成为浏览器草稿，点击保存才写入当前 worktree。
- 保存配置不等于 Git 提交、推送或发布；发布继续使用既有安全 Git 工作流。
- 配置文件被外部程序修改后，工作台必须检测版本冲突并拒绝静默覆盖。

### 10.6 SEO 与 GEO 验收要求

- 自动生成与可见页面内容一致的 `WebSite`、`Person`、`BlogPosting` 和 `BreadcrumbList` JSON-LD。
- 生成并校验 `robots.txt`、`sitemap.xml`、RSS/Atom；可选生成标注为实验性标准的 `llms.txt`。
- 分别控制搜索发现与模型训练爬虫，不把二者合并为单一“允许 AI”开关。
- 默认允许 AI 搜索发现，默认禁止模型训练；用户可在设置中明确修改。
- 首期至少支持 Googlebot、Google-Extended、OAI-SearchBot 和 GPTBot，并允许 Schema 后续增加爬虫规则。
- 文章级检查覆盖标题层级、摘要、作者、发布时间、更新时间、canonical、图片替代文本、引用链接和文本可访问性。
- 后台只展示确定性的完整性检查，不承诺排名，也不生成不可解释的 SEO/GEO 综合分数。

### 10.7 安全与一致性

- 设置 API 只能修改配置文件、栏目首页、文章和白名单公开资源目录。
- 不提供任意路径读写、任意配置代码执行或任意 shell 命令入口。
- Token、API Key、Webhook 密钥、SSH 私钥和 Vercel 凭据不得进入配置文件或浏览器状态。
- 配置保存使用内容哈希进行乐观并发控制，并采用临时文件加原子 rename。
- 新建栏目涉及多文件变更时必须按事务处理；失败后恢复旧配置并清理仅由本次操作新建的临时文件。
- 所有配置修改必须能在提交前查看 Git Diff，并能通过 Git 历史恢复。

### 10.8 v1.1 不在范围

- 从后台直接管理 Vercel 账号、项目或部署凭据。
- 保存任何秘密值；仅允许显示所需环境变量是否存在。
- 多语言内容编辑、一键翻译和翻译供应商接入。
- 自动迁移已有栏目物理目录或批量修改公开 URL。
- GEO 排名承诺、黑盒评分或关键词堆砌工具。
