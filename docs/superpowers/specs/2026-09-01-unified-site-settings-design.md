# 统一站点设置中心设计规格

| 项目 | 内容 |
| --- | --- |
| 状态 | Awaiting implementation planning |
| 日期 | 2026-09-01 |
| 工作分支 | `codex/editorial-cms` |
| 产品基线 | `specs/editorial-cms/PRD.md` v1.1 |
| 技术基线 | `specs/editorial-cms/DESIGN.md` v1.1 |

## 1. 目的

将现有本地文章编辑器扩展为仓库的可视化管理 UI，并消除网站与编辑器各自硬编码栏目和站点信息的问题。公开网站继续由 VitePress 静态构建，所有可发布内容和设置继续存放在 Git 仓库中。

## 2. 已确认范围

- 建立 `config/site.config.json` 单一配置源。
- 建立共享 TypeScript Schema，提供类型、默认值、校验和迁移。
- 网站导航、侧边栏和编辑器目录树使用同一栏目树。
- 新增完整站点设置中心，管理所有常见公开设置。
- 新增可扩展栏目管理；新建自动创建栏目首页，删除只归档。
- 新增 SEO 与 GEO 配置和确定性检查。
- 第一版只编辑中文，但为多语言和未来一键翻译预留数据结构。
- 继续沿用本地 Git、GitHub PR 和 Vercel 自动部署，不接入 Vercel 凭据。

## 3. 不在本轮范围

- 多语言编辑和翻译服务接入。
- 栏目物理目录批量迁移及自动重定向。
- 线上管理端、登录、数据库和多用户权限。
- 任意 VitePress 代码配置编辑。
- 密钥保存、Vercel API 管理和直接生产部署。
- GEO 排名承诺、黑盒分数或非官方排名技巧。

## 4. 单一事实来源

`config/site.config.json` 保存站点公开配置；`docs/zh` 保存中文 Markdown；`docs/public` 保存公开资源。`packages/site-schema` 是工作台和 VitePress 的唯一配置解析入口。

任何消费者不得直接信任原始 JSON。读取流程必须是：加载 JSON、检查 `schemaVersion`、迁移旧版本、Schema 解析、业务一致性校验、输出只读标准化配置。

## 5. 配置域

- `site`：站点名、描述、规范域名和语言。
- `branding`：Logo、favicon、分享图和 alt。
- `author`：姓名、简介、头像和公开身份链接。
- `locales`：语言根目录、语言名称和启用状态。
- `sections`：栏目稳定 ID、名称、目录、路由、父级、排序和状态。
- `navigation`：内部栏目引用或外部链接。
- `homepage`：首页模块和推荐文章引用。
- `appearance`：主题、强调色、布局和代码主题。
- `seo`：标题、canonical、索引、Open Graph、sitemap 和结构化数据开关。
- `geo`：AI 爬虫策略、实验性输出及内容完整性策略。
- `footer`：版权、备案、友情链接和社交链接。
- `integrations`：仅公开标识和秘密环境变量名称，不含秘密值。

完整字段在实施计划第一阶段通过 Schema 测试固定；未列明字段不得在 UI 中先行发明。

## 6. 栏目不变量

1. `id` 在所有语言和历史版本中稳定且唯一。
2. `directory` 必须位于 locale 内容根目录内。
3. `route` 在同一 locale 内唯一并以 `/` 开头。
4. `parentId` 只能引用同 locale 栏目，栏目图必须无环。
5. 有文章的栏目不能通过普通设置修改目录或路由。
6. `archived` 栏目保留目录与文章，不出现在新建文章选项和公开导航中。
7. 编辑器和网站使用同一树构建函数、排序规则和状态过滤规则。

## 7. UI 工作流

顶部切换“文章管理”和“站点设置”。文章管理左侧展示真实栏目目录树；搜索结果可扁平化。右栏在原有预览/大纲之外增加文章级 SEO/GEO 检查。

站点设置左栏展示设置分组，中栏展示表单，右栏展示效果预览、Schema 问题和 Git Diff。表单具有未保存状态，不直接写文件。保存成功只代表写入 worktree，不代表提交、推送或发布。

新增栏目向导收集名称、slug、父栏目、导航位置和默认折叠状态，预览将创建的配置项、目录和 `index.md` 后再确认。归档操作展示受影响文章数量，但不删除任何文件。

## 8. 安全保存

- `GET /api/settings` 返回配置与内容哈希。
- 保存请求携带 `baseHash`；服务端检测到外部修改时返回 `409`。
- 所有文件路径由服务端根据 Schema 和稳定 ID 生成。
- JSON 使用同目录临时文件与原子 rename。
- 多文件栏目操作记录事务目标；失败时恢复旧配置，只撤销本次创建内容。
- Git 提交只暂存本次设置会话记录的精确文件集合。
- API 保持回环 Host/Origin 检查，不接受跨站请求。

## 9. VitePress 集成

VitePress 配置文件变为适配层：从标准化配置生成站点元数据、主题配置、导航、侧边栏、页脚、社交链接、SEO/GEO head 标签及生成器输入。高级插件仍在 TypeScript 中显式配置。

公开构建继续执行 `pnpm build:site` 并输出 `apps/site/dist`。Vercel 连接 GitHub 生产分支；内容分支用于 Preview，合并到生产分支后自动部署。管理端不与 Vercel 账号直接关联。

## 10. SEO/GEO

SEO 和 GEO 共享文章元数据，但权限与输出分开配置。系统生成 `WebSite`、`Person`、`BlogPosting` 和 `BreadcrumbList` JSON-LD，且字段必须来自页面可见内容。

默认允许 Googlebot 和 OAI-SearchBot 搜索发现，禁止 GPTBot 和 Google-Extended 用于训练或扩展。`llms.txt` 作为实验性开关，默认关闭。后台提供字段缺失、标题结构、图片 alt、引用链接、canonical 和作者/更新时间等明确检查，不显示综合排名分数。

## 11. 多语言扩展点

第一版 UI 只允许中文 locale。栏目和文章引用使用稳定 ID，而非显示名称。未来翻译模块可以增加源文章 ID、目标 locale、翻译状态、源内容哈希和供应商任务记录，不需要改变栏目或站点配置的基本形状。

## 12. 验收标准

- 新增栏目后，网站和编辑器出现相同层级、顺序和文章路径。
- 归档栏目不删除任何文章，且不会再出现在公开导航和新建分类中。
- 修改基础、导航、SEO/GEO 或页脚设置后，VitePress 构建输出正确变化。
- 无效配置无法保存，也无法通过站点构建。
- 外部修改配置后，旧浏览器草稿不能静默覆盖。
- Token、API Key、Webhook、SSH 和 Vercel 凭据不出现在配置、请求响应或 Git diff 中。
- 所有测试、类型检查和两套构建通过，公开产物不存在管理端路由。

## 13. 实施顺序建议

1. 共享 Schema、默认配置和迁移框架。
2. VitePress 适配层和网站回归测试。
3. 共享栏目树与编辑器目录树。
4. 设置读取、校验、并发保存 API。
5. 设置中心 UI 和配置 Diff。
6. 栏目新增/归档事务。
7. SEO/GEO 生成器与文章完整性检查。
8. 浏览器验收、构建隔离和使用文档。

下一对话应先使用 writing-plans 技能，将本规格拆成可执行的 TDD 实施计划；不要直接开始修改代码。
